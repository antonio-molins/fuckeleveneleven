# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Fuck 11:11": a static, single-page Astro site parodying "11:11, make a wish" influencers. It counts down to the next place where the local clock reads 11:11, and the wish box can never accept a wish. There is no backend by design, and wish text must never leave the browser (no fetch, analytics or storage of it).

## Commands

- `npm run dev` / `npm run build` / `npm run preview`
- `npm run check`: `astro check` (TypeScript + Astro diagnostics)
- `npm test`: Vitest unit tests in `tests/`. Single test: `npx vitest run tests/elevenEleven.test.ts -t "wraps past midnight"`
- `npm run test:e2e`: Playwright (desktop + Pixel 7) against a built `astro preview` on port 4111. Single test: `npx playwright test -g "portal state" --project=desktop`
- Astro 7 auto-backgrounds `astro dev`/`astro preview` when it detects an agent. Use `astro preview stop` / `status` / `logs` to manage it. The Playwright config passes `--ignore-lock` to keep its server in the foreground; don't remove it.

## Architecture

- `src/lib/elevenEleven.ts`: pure timezone math, fully unit-tested.
  - `getOffsets()` groups IANA zones by their current UTC offset (via `Intl` `longOffset`, so DST is respected).
  - `nextElevenEleven()` treats 11:11 and 23:11 as one target modulo 12h, and returns the soonest start. All offset groups that tie are merged; zones 12h apart hit 11:11 together.
  - `isNow` holds for the whole 11:11 minute.
  - ICU returns legacy names (`Asia/Calcutta`, `Asia/Katmandu`), which `prettyZone` aliases.
- `src/data/cityCounts.json`: number of GeoNames cities of 15,000+ people per IANA zone, generated by `node scripts/build-city-counts.mjs path/to/cities15000.txt` (download `cities15000.zip` from download.geonames.org). It's CC BY 4.0, so keep the footer credit. Engines name some zones differently from GeoNames (`Asia/Calcutta` vs `Asia/Kolkata`), so look counts up via `indexCityCounts`/`citiesIn`, which normalize both sides with `Intl`.
- `src/components/Countdown.astro`: client script ticks every 250ms. It regroups offsets whenever the target changes, toggles `body.is-now`, and drives the story progress bar through the `--progress` CSS variable.
- `src/lib/sabotage/`: each sabotage implements `Sabotage` from `types.ts`.
  - `attach(els)` provides live mischief and returns a cleanup function.
  - `reject(wish, els)` resolves to the rejection message.
  - `pickSabotages()` picks a random 1–2, never `flee` under `prefers-reduced-motion`, and never anything from the previous round (`previous`).
  - `flee` dodges only while the wish box has text, a random 2–5 times per arming (`data-max-dodges`), at most once per approach (after each dodge, and when armed under the cursor right after a click, it stays calm until the cursor has left its panic radius), always landing away from both the pointer and its old spot. `isCaught(form)` says when it lets itself be pressed.
- `src/lib/scribble.ts` + the strike script in `index.astro`: the "make a wish" strike-through is one perfect-freehand stroke. Pen points are sampled at even *time* steps with eased passes, so revealing one point per frame draws fast mid-pass and slow at turns, and simulated pressure thickens the ink at the turns. The server renders it finished (no-JS and reduced motion). The script redraws it live after the fonts gate, then dispatches `strike:done`, which the mobile intro waits for. The crayon grain is the `#crayon` SVG filter.
- `src/components/WishForm.astro`: on every submit it always rejects, then re-rolls the sabotages. It exposes `data-sabotage` (active ids) and `data-attempts` (incremented once a submit fully settles) for e2e tests to wait on.
- Layout: `.stage` is a size container filling the space above the footer. `.story` is a 9:16 box whose width (`--story-w`) comes from the stage's `cqw`/`cqh`, and its `font-size` is a fraction of that width. Size everything inside the story in `em`, not `rem`/`vw`, so it scales like a screenshot. The paywall `<dialog>` sits inside the story in the DOM, so it resets `font-size` to rem.
- Visual concept: a pastel influencer Instagram story (Cormorant Garamond italic), vandalised in Permanent Marker. Fonts are self-hosted through `@fontsource`; don't add external font or CDN requests. The one outside request is GoatCounter (pinned `count.v5.js` with SRI in `index.astro`; it skips localhost). Events go through `src/lib/track.ts` or `data-goatcounter-click` and must only ever be fixed names, never anything the visitor typed. The e2e tests block the script, audit outgoing hosts, and check that no wish text reaches an event. Tokens are at the top of `src/styles/global.css`.

## Gotchas

- Served at the root of `fuckeleveneleven.com` (custom domain on this repo's GitHub Pages project site; `antonio-molins.github.io/fuckeleveneleven` redirects there). Asset links still go through `import.meta.env.BASE_URL` so a base path can come back without edits.
- Mobile intro (`html.intro`, set by the inline script in `index.astro`): the hero is drawn first in light ink, the manifesto types in below it once the strike-through's `animationend` fires, then the phone fades in around the hero, which never moves. A `fonts-loading` class hides the page until the display fonts load (max 1.5s). The inline script must stay *after* the viewport meta. Before that tag is parsed, mobile browsers report a ~980px layout width and the intro never starts.
- Desktop reveal (`html.reveal`, set by the same inline script; never under reduced motion): the phone starts centred on the page (shifted by half the manifesto column plus the gap, `--manifesto-w`/`--stage-gap`), minus the countdown sticker. After the strike-through, `html.reveal-writing` slides it over while the manifesto types in beside it, with the same code as the mobile intro. Then the sticker flies in and the city count starts once the jab is fully visible. A click skips it; `open(page)` also waits for the slide to finish.
- In e2e, use the `open(page)` helper. It taps through the mobile intro or the desktop reveal. Tests asserting exact countdown values install the clock a little early and `pauseAt` the target time after `open`, because the intro takes real seconds.
- In e2e, `page.clock` mocks JS time, but CSS animations run on real time. The hero scrawl animates in over about 1.6s, so wait before screenshots.
- When picking a fixed time for a "which city is next" test, remember that whole and half-hour offsets hit 11:11 at :11 and :41 UTC past the hour, and +x:45 offsets hit it at :26.
